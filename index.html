Recovery and retained files

Only an incomplete final WAL frame is truncated on startup. Complete frames with invalid headers or checksums stop recovery. SHA-256 protects run-file integrity. These checks detect accidental corruption; they are not authentication.

Unreferenced runs are retained for inspection, not deleted automatically. A crashed process can leave a writer.lock; stop its owner before manually removing that stale lock. File contents are fsynced, but directory entries are not, so this demo does not promise power-loss durability.

Every version has a sequence. Every live run has a manifest entry.
